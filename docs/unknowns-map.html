01

已知的已知

已经定下来的产品边界。

  • 产品叫 PackCaptain，命令名暂用 packcaptain，不做 macOS 图形应用。
  • 首批支持 Claude Code、Codex、Pi，展示本地 skills 的来源、scope 与状态，并支持单项开关。
  • Preset 是本地 skills 的命名分组，定义全局共用，启停状态属于具体 target。Target 是 agent 与 scope 的组合。
  • 应用时选择 agent，并可多选项目批量操作。同一个 target 可以同时开启多个 presets。
  • 全局作为基础、项目作为补充。项目操作不屏蔽全局 skill；实际加载结果遵循各 agent 的原生规则。
  • 初始化扫描 agent 目录并列出候选项目，由用户勾选纳入管理。之后可以主动添加目录。
  • 用户从本地 skills 手动选择 preset 成员。第一版不自动导入作者整合包，不建设商店或展示依赖关系。
  • Agent 入口采用非交互 CLI 与 JSON 输出。TUI 和 CLI 共用同一套管理规则，第一版不另建 MCP 或 HTTP 服务。
  • 统计只读取容易、稳定获取的现成数据。没有可用数据就不显示，不自建采集，不阻塞核心功能。
核心工作流。发现本地 skills，手动创建 preset，选择管理目标，预览影响，再批量启停。切换作者套装不是强制互斥；用户可以自行关 A、开 B，也可以同时开启 A 和 B。

文件依据为 GLOSSARY.md、Preset ADR 与 agent 入口调研。其余条目来源于本次会话中用户确认。

已知的未知

Decision ledger。产品决定已关闭，技术 OPEN 见验证门。

分组而非模式 user
Preset 是可组合的配套 skill 集合，不是互斥模式或完整快照。原因是同一项目可能同时需要多套整合包。
共享成员按并集保护 user
关闭一个 preset 时，仍被其他已开启 preset 需要的 skill 不关闭。单项手动关闭仍允许。
重新开启整组覆盖此前单项关闭 user
明确开启 preset 时，全部可用成员开启。这是用户本次整组开启的明确意图，不设永久阻挡状态。
修改定义后确认同步 user
展示成员变更，确认后同步到已开启该 preset 的 targets。未开启该 preset 的目标不受影响。
同步时允许保留或恢复手动关闭 user
仅在存在相关旧成员时显示选择。TUI 预选保持关闭，用户确认后执行；选择只影响本次同步。
恢复范围限定 user · 已整体签收
仅处理当前 preset 中仍保留的相关旧成员及所选 targets。新增成员正常开启；缺失或不支持不算手动关闭。
非交互调用必须显式处理冲突 user · 已整体签收
拟采用 --closed-members=keep|restore。存在冲突而未给策略时，返回影响清单和错误，不写入。
项目由用户认领 user
扫描只发现候选，不自动纳入管理；后续可添加指定目录。多项目通过多选满足，本轮没有另外确定命名项目组的需求。
CLI 优先 user 委托 · 调研后已签收
采用成熟的非交互命令与 JSON 输出惯例，减少第一版接入成本。不是认定 MCP 不成熟，也不是假定 Pi 不支持 MCP。
装饰性统计不扩张为采集工程 user
不建设 hooks、埋点、遥测接收器或独立统计账本。没有稳定可读数据就不做。
名字确定 user
PackCaptain 表达整合包与管理者的感觉。公开搜索未发现明确同名独立软件，但包名、域名和商标未完成核验。
03

未知的已知

通过具体例子抽出来的偏好与工作习惯。

  • 消费者是终端用户，也包括他们调用的 agents。这让非交互接口成为第一版需求，而不是用自动按键控制 TUI。
  • 整合包比配置模式更贴近心智。用户想体验不同工程师的配套 skills，也可能组合使用。这改变了 preset 的可组合性与共享成员规则。
  • 明确点击开启整组，就是全开。这否定了持续拦截整组开启的手动关闭覆盖方案。
  • 用具体选项控制例外。编辑分组与重新开启分组分开处理，保留或恢复旧成员由本次选择决定。
  • 项目数量多。这让初始化发现后勾选，以及多项目批量应用进入第一版。
  • 界面参考可搜索多选列表。采用搜索、方向键移动、空格勾选、回车确认的交互方向。参考来自用户提供的截图，不是尚未制作的产品原型。
  • 用户反对冗余。Preset 是中心，统计是装饰。商店、依赖求解和多套接口不进入第一版。
  • 名字必须有管理感。纯材质和氛围名字被放弃，同名独立软件原则上排除，最终选择 PackCaptain。

未知的未知

盲点与边界。发现已披露，但不伪装成已经实测。

DECIDED多个 preset 重叠

直接逐组删除入口会误关共享成员。已决定保护仍被其他开启组需要的成员，并允许单项调整。

证据为用户给出的 A、B、C 项目与多组并存场景，以及 Preset ADR。

SHARP EDGE共享源文件不能当入口删除

停用某个 target 不得删除其他 targets 共用的 skill 内容。软链接是可选机制，不是已确定实现，也不能统计使用次数。

这是文件管理的设计风险，实际共享关系尚未扫描；写入前必须核验。

OPEN各 agent 加载与停用能力不同

不能用统一的目录假设冒充有效状态。需核验所支持版本的发现路径、同名解析、停用机制和是否需要新会话生效。

已读 Claude Skills 与 Pi Skills。实际适配机制仍未实现或验证。

DECIDED原生事件不等于现成统计结果

Claude 有原生报告，Codex 有原生事件，这不自动意味着存在稳定的累计统计接口。不为装饰性数字建设采集系统。

依据 Claude skill-doctor 和 Codex 固定版本文档。CodeBurn 的完整截图计数与成本公式未核实。

SHARP EDGE扫描不是授权写入

候选目录要由用户认领；用户全局目录不能误归为项目。CLI 必须明确 targets，不能缺省改所有项目。

GATE

实现者写代码前要确认的事实

没有阻塞需求澄清的 OPEN。以下是技术验证门，不是可以静默忽略的脚注。允许进入隔离环境调查与实现准备；相关验证通过前，不对真实 agent 安装目录执行写入。

  1. OPEN · Agent 能力。核验 Claude Code、Codex、Pi 支持版本的项目与用户级路径、链接处理、同名解析、停用和刷新行为。用临时目录里的最小 skills 验证，给每种适配器记录结果。
  2. OPEN · 安全入口管理。区分真实文件、符号链接与已有非托管入口。验证共享源保护、外部变更、失败回滚、并发写入和幂等重试；未经验证不操作真实 skills。
  3. OPEN · 身份与状态存储。确定重复名称、同源多入口、移动目录、失效路径的识别规则。可靠地区分手动关闭、缺失与不支持，不能从入口缺失猜测用户意图。
  4. OPEN · 项目扫描。验证扫描范围、权限失败、链接循环和候选根目录识别。扫描不修改文件，明确说明漏扫范围。没有 agent 配置目录的项目仍可由用户主动添加。
  5. OPEN · 技术栈与成熟依赖。根据 TUI、分发和文件管理需要选择成熟库。尚未选择语言、TUI 框架或存储格式，不把这些当成已批准方案。
  6. OPEN · 可选统计与名称发布。只有现成统计接口足够稳定才接入；否则跳过。发布或注册前核验实际分发渠道的包名。两项都不阻塞 preset 开发。

正式 issue 与 spec 遵循 仓库 GitHub Issues 约定。本轮没有发布 issue、提交或推送，也没有改动 agent 配置。
